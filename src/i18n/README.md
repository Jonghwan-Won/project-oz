# 문구와 다국어

## 2026-10-21 한국어·영어 콘텐츠 지원으로 변경

최신 정책은 한국어·영어 두 언어 지원이다. Project에는 공통 정보를, ProjectTranslation에는 locale(ko/en), title, summary, body, bodySchemaVersion을 저장한다. 아래 원문 단일 저장·번역 제거 기록은 당시 이력이며 이 정책으로 대체한다. 게시글 DB 도입 시에도 Post와 PostTranslation을 분리한다. 게시글 테이블·관리자 영어 입력·공개 화면 DB 조회·언어 버튼 변경은 아직 구현하지 않았다.


공개 페이지·메뉴·프로젝트의 한국어 UI 문구는 `ko.ts`, 영어는 `en.ts`에서 관리합니다. 서버 페이지는 `getMessages()`로 선택된 사전을 읽으며 영어는 같은 `Messages` 타입을 만족해야 합니다. 클라이언트 컴포넌트에는 필요한 labels만 전달합니다. 오류 복구 문구는 서버 조회 실패에도 표시할 수 있도록 `errors.ts`에 별도로 둡니다.

헤더의 지구본 아이콘에서 한국어·영어를 선택합니다. Server Action이 허용된 언어만 검증해 `ddoza-locale` 쿠키에 1년간 저장하고 페이지를 다시 렌더링합니다. 기본값과 잘못된 쿠키의 대체값은 한국어입니다. 현재 경로·검색 조건·해시를 유지하며 `html lang`과 메타데이터도 변경합니다. 사용자 작성 게시글의 제목·요약·본문은 번역하지 않으며 src/content/site.ts의 원문을 그대로 표시합니다. 추후 DB에서도 저장된 원문을 조회합니다. 기록 카테고리의 표시 이름만 번역하고 기존 검색 값은 유지합니다. 프로젝트 유형은 언어와 무관한 코드를 검색 값으로 사용합니다.

현재는 같은 URL을 사용하는 쿠키 기반 언어 전환입니다. 언어별 검색엔진 색인이나 `/ko`·`/en` 경로, hreflang은 구현하지 않았습니다. 언어 쿠키를 읽는 공개 페이지는 요청 시 서버에서 렌더링하며 사용자별 응답에 공용 캐시를 적용하지 않습니다.

`/error`는 404 디자인 확인 화면이고 실제 없는 주소는 `not-found.tsx`가 HTTP 404로 처리합니다. `error.tsx`와 `global-error.tsx`는 일반 오류와 루트 레이아웃 오류를 처리하며 재시도 버튼을 제공합니다. 오류 원문·스택은 화면에 표시하지 않습니다.

번역 파일에는 JSX나 HTML을 넣지 않습니다. 강조할 부분은 `heroStart`, `heroHighlight`, `heroEnd`처럼 의미 단위로 분리하고 렌더링은 페이지에서 처리합니다. 언어마다 어순이 달라 이 구성이 맞지 않으면 해당 문구의 구조를 조정합니다.

## 공통 텍스트 효과

```tsx
<mark className="textHighlight">새로운</mark>
<h2 className="accentDot">아이디어가 현실이 되는 곳</h2>
```

`textHighlight`는 바이올렛 배경과 어두운 글자색을 적용합니다. `accentDot`은 장식용 바이올렛 네모점을 붙입니다. 두 클래스 모두 부모 글자 크기를 따릅니다. 온점은 CSS 장식이므로 번역 문구 끝에 마침표를 중복해서 넣지 않습니다. 물음표 등 본래 문장부호가 필요한 문구는 유지합니다. 폼의 필수 입력 의미와 혼동하지 않도록 `required`라는 클래스명은 사용하지 않습니다.

## 2026-10-21 언어 토글

지구본(한국어 화면)을 누르면 영어, 태극문양(영어 화면)을 누르면 한국어로 즉시 전환한다. 드롭다운은 사용하지 않으며 쿠키·현재 경로 유지·진행/실패 알림은 유지한다. 공개 프로젝트 내용은 DB 번역을 조회한다. 게시글 원문 정책은 게시글 DB 구현 시 별도 적용한다.
