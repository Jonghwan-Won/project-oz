# 개발 콘텐츠 운영 이관

이관 묶음은 개발 oz_dev의 공통코드, 프로젝트, 게시글과 연결된 첨부파일만 포함한다. AuthUser/AuthAccount/AuthSession/AuthVerification, Inquiry, Prisma migration 이력은 복사하지 않는다. 글/프로젝트의 공개 여부와 삭제 상태를 그대로 보존한다.

2026-10-30 준비한 스냅샷: 공통코드 그룹 6개, 코드 72개, 프로젝트 8개, 게시글 15개, 연결된 첨부 31개. 실제 파일의 SHA-256을 포함한다. 사용하지 않는 첨부는 제외한다. 개발 원본은 삭제하지 않는다.

## 준비된 NAS 파일

`/volume1/docker/project-oz/transfer/20261030-content`에 content.json, content-transfer.mjs, deploy-content.sh를 복사했다. content.json에는 비공개 콘텐츠도 있으므로 웹에 공개하거나 Git에 커밋하지 않는다. 실행 스크립트는 이 폴더를 700, JSON을 600 권한으로 제한한다. 이관 완료 후 검증까지 보관하고, 이후 NAS에서 안전하게 정리한다.

## 실행

이번 코드의 Check와 Build web image가 모두 성공한 전체 커밋 SHA를 사용한다. NAS SSH에서 다음 명령을 실행한다.

```sh
sudo sh /volume1/docker/project-oz/transfer/20261030-content/deploy-content.sh 전체_커밋_SHA
```

스크립트는 운영 Project/Post가 비어 있는지 먼저 확인한다. 기존 콘텐츠가 있으면 덮어쓰지 않고 중단한다. 사용자가 운영에 직접 등록한 글/프로젝트가 없다고 확인한 조건이다. 기존 테스트 업로드 등 미사용 Asset은 삭제하지 않는다.

1. 성공한 웹/migration 이미지를 먼저 내려받는다.
2. 운영 웹을 정지해 쓰기를 막는다.
3. 운영 전체 DB를 custom dump로 백업하고 pg_restore로 목록을 읽어 확인한다. 운영 uploads도 tar로 백업한다.
4. 운영 DB migration을 적용한다. 새 공통코드와 앱은 함께 전환해야 한다.
5. 실제 운영 DB 트랜잭션에서 이관을 시험하고 롤백한다. 기존 기본 Tag는 kind/slug로 매핑해서 FK를 보존한다.
6. 실제 이관 트랜잭션을 수행한다. source/target DB 이름, 제약조건, 행 수, 인증 사용자/계정 수를 확인한다. 공통코드 이름/정렬/활성 상태는 개발 값을 반영하며, 기존 운영에만 있는 코드는 삭제하지 않는다.
7. 파일을 NAS uploads-dev에서 uploads로 복사하고 체크섬을 검증한 뒤 커밋한다. 다른 내용의 파일을 덮어쓰지 않는다. 새 파일과 연월 폴더에 웹 사용자 1000의 권한을 설정한다. 커밋 결과가 불확실하면 파일을 삭제하지 않는다.
8. 이전 웹은 복구용 컨테이너로 보관하고 새 이미지에 동일한 .env.web, uploads/logs 볼륨을 연결한다. health/projects/board 응답을 확인한다.

## 검증과 실패 시

기존 GitHub 로그인이 유지되는지, 공개 프로젝트 8개와 공개 게시글 수가 맞는지, 비공개 글은 비공개로 남는지, 이미지/첨부와 한영 분류명이 맞는지 확인한다. 프로젝트·게시글 내용과 실제 첨부파일 검증을 마칠 때까지 백업을 보관한다.

백업 경로는 `/volume1/docker/project-oz/backups/content-import-UTC시각`이다. 오류가 나면 스크립트를 반복 실행하지 말고 마지막 단계와 백업 경로를 확인한다. migration 이후의 이전 이미지 단독 시작은 호환되지 않을 수 있다. DB 복원이 필요한지와 새 이미지 문제인지를 먼저 판단한다. 실제 import 커밋 이후 재실행하면 Project/Post 비어 있음 검사가 막는다.

이관 스크립트의 check는 DB 쓰기를 트랜잭션으로 시험한 후 롤백한다. 파일은 복사하지 않는다. 스냅샷 이후 개발 콘텐츠를 수정하거나 원본 첨부를 삭제하면 새 export가 필요하다.
