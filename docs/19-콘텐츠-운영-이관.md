# 개발 콘텐츠 운영 이관

## 용도와 범위

이관 도구는 개발 DB의 공통코드, 프로젝트, 게시글과 연결 첨부파일을 빈 운영 콘텐츠 DB로 옮기는 최초 이관용입니다. 일반 이미지 업데이트나 기존 운영 콘텐츠 동기화에 사용하지 않습니다. 기존 최초 이관은 완료된 상태이며 재실행 전 대상과 필요성을 확인해야 합니다.

인증 사용자·계정·세션·검증 정보, 문의, Prisma migration 이력은 복사하지 않습니다. 글·프로젝트의 공개 여부와 삭제 상태를 보존하며, 사용하지 않는 첨부는 제외하고 개발 원본은 삭제하지 않습니다. 이관 묶음에는 파일 체크섬이 포함됩니다.

## 민감 자료 관리

이관 JSON에는 비공개 본문과 파일 메타데이터가 포함될 수 있습니다. JSON, DB dump, 파일 백업과 실제 배포 설정은 Git·이미지·공개 파일 저장소에 넣지 않습니다. 작업 디렉터리는 운영자만 접근하도록 하고 JSON과 백업도 제한된 권한으로 보관합니다. 실제 위치·실행 시각·행 수·백업 목록은 비공개 운영 기록에서 관리합니다.

## 도구와 사전 조건

- scripts/content-transfer.mjs의 export는 개발 콘텐츠를 내보냅니다. check는 대상 DB 쓰기를 트랜잭션으로 시험하고 롤백하며 파일은 복사하지 않습니다. apply는 실제 이관을 수행합니다.
- scripts/deploy-content.sh는 호스트 경로·이미지·컨테이너 이름에 맞춘 운영용 스크립트입니다. 소스의 설정을 검토하고 실제 환경과 대조한 후 사용해야 합니다. 경로와 이름을 일반 배포 표준으로 취급하지 않습니다.
- Project/Post가 이미 있는 운영 DB에는 이관하지 않습니다. 기존 콘텐츠를 덮어쓰지 않으며 미사용 Asset도 삭제하지 않습니다.
- 스냅샷 이후 개발 콘텐츠나 첨부가 바뀌면 새 export가 필요합니다.

## 실행 순서

1. 검사에 성공한 동일 커밋 SHA의 웹·migration 이미지와 이관 묶음을 준비합니다.
2. 운영 쓰기를 중지하고 DB와 업로드를 함께 백업합니다. DB 백업은 복원 목록을 읽어 확인합니다.
3. migration을 적용하고 check로 제약·매핑을 검증합니다. 기존 Tag는 kind/slug로 매핑합니다.
4. apply로 이관합니다. 기존 운영에만 있는 공통코드는 삭제하지 않으며 인증·문의 데이터는 유지합니다.
5. 파일을 복사하고 체크섬과 웹 사용자 접근 권한을 확인한 뒤 커밋합니다. 다른 내용의 파일을 덮어쓰지 않으며 커밋 결과가 불확실하면 파일을 삭제하지 않습니다.
6. 이전 호환 이미지를 보관하고 새 웹에 기존 환경변수와 파일·로그 볼륨을 연결합니다.
7. 로그인, 공개·비공개 조회, 이미지·첨부 접근, 분류명을 확인합니다. health 응답은 DB와 권한 검증을 대신하지 않습니다.

## 실패와 복구

실패하면 자동 재실행하지 말고 마지막 성공 단계·DB 커밋 상태·백업을 확인합니다. 이미 import가 커밋됐다면 빈 콘텐츠 검사가 재실행을 차단합니다. migration 이후 이전 앱만 다시 실행하면 호환되지 않을 수 있으므로 이미지 문제와 DB 복원 필요성을 구분합니다.

DB와 파일의 실제 복원 검증은 별도로 수행합니다. 성공한 이관이나 백업 파일 생성만으로 복구 가능성을 보증하지 않습니다. [배포·운영](06-배포-운영.md)과 [현재 구현 상태](10-현재-구현-상태.md)를 참고하세요.
