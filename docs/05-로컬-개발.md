# 로컬 개발

## 준비

- Node.js 24.18.x (`.node-version` 및 `package.json` 기준)
- 저장소 루트에서 `npm ci` 후 `npm run dev`
- 프로젝트·게시글·문의 및 로그인 기능은 PostgreSQL 연결과 해당 migration이 필요합니다. UI만 확인할 때는 DB 없이 실행할 수 있습니다.

## 환경변수

비밀값은 저장소에 넣지 말고 로컬 `.env.local`에서 관리합니다. Prisma 설정은 `.env.local`의 `MIGRATION_DATABASE_URL`을 우선 사용하고, 없으면 `DATABASE_URL`을 사용합니다.

| 변수                                       | 용도                                      |
| ------------------------------------------ | ----------------------------------------- |
| `DATABASE_URL`                             | 개발 앱 계정의 PostgreSQL 연결            |
| `MIGRATION_DATABASE_URL`                   | 개발 migration 계정 연결                  |
| `STORAGE_ROOT`                             | 개발 업로드 파일의 영속 저장 위치         |
| `BETTER_AUTH_URL`                          | 로컬 앱 주소(예: `http://127.0.0.1:3000`) |
| `BETTER_AUTH_SECRET`                       | 인증 비밀키, 32자 이상                    |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | 개발용 GitHub OAuth 앱                    |
| `GITHUB_ADMIN_ID`                          | 허용할 관리자의 GitHub 숫자 ID            |

GitHub OAuth 앱의 callback은 `BETTER_AUTH_URL`에 `/api/auth/callback/github`를 붙인 주소입니다. 운영 OAuth 앱과 키를 개발에 재사용하지 마세요. 인증 변수나 DB가 없으면 인증/DB 기능은 작동하지 않습니다.

## NAS 개발 DB 연결

NAS 개발 DB에 연결하는 경우 SSH 터널을 별도 PowerShell에서 유지합니다. 아래 대문자 항목은 실제 환경 값으로 바꿉니다.

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:15432:DEV_DB_CONTAINER_IP:5432 SSH_USER@NAS_SSH_HOST
```

개발 앱 계정으로 `.env.local`의 `DATABASE_URL`을 로컬 터널 주소에 연결합니다. 예시:

```dotenv
DATABASE_URL="postgresql://DEV_APP_USER:URL_ENCODED_PASSWORD@127.0.0.1:15432/oz_dev"
```

외부 PC에서는 NAS의 Tailscale 주소를 SSH 접속에 사용합니다. 운영 DB를 개발에 연결하지 말고, 실제 주소·비밀번호를 문서나 채팅에 남기지 마세요. 개별 PC용 PostgreSQL Compose는 `docker/compose.dev.yml`에 별도 대안으로 있습니다.

## 데이터베이스 명령

```powershell
npm run db:validate
npm run db:generate
npm run db:migrate:dev -- --name change_name
npm run db:seed
```

개발 migration은 로컬 개발 DB에서만 만듭니다. 적용된 migration을 수정하지 말고 새 migration을 추가하세요. 운영에는 `migrate deploy`만 사용하며, 운영 데이터에 `migrate reset`이나 개발용 `db push`를 실행하지 않습니다. 실제 스키마와 운영 순서는 [데이터베이스](03-데이터베이스.md), [배포·운영](06-배포-운영.md)을 참고하세요.

## 가이드와 문서

공통 UI 가이드는 공개 예제로 제공됩니다. 내부 Markdown 문서와 환경 구조도는 관리자 세션으로 보호하며, DB 진단 API는 개발 환경의 관리자만 사용할 수 있습니다. DB 진단은 SELECT 1 연결 확인으로 migration이나 CRUD 검증을 대신하지 않습니다.

## PC별 설정

운영 설정과 각 PC의 .env.local은 별개이며 Git으로 동기화되지 않습니다. 개발 OAuth 설정, DB 터널, STORAGE_ROOT와 선택 사항인 LOG_ROOT를 각 PC에서 준비합니다. 실제 주소·공유 폴더 경로는 비공개 설정으로 관리하고 개발 파일과 로그는 운영 저장소와 분리합니다.

경로 존재 여부만으로 쓰기 권한이나 업로드가 검증되지는 않습니다. 파일을 이동할 때는 기존 파일과 DB 상대 키의 대응을 유지하고 이동 결과를 확인한 뒤 환경변수를 변경합니다. [로그 설정](17-운영-로그.md)을 참고하세요.
