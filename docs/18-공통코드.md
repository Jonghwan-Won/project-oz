# 공통코드 기준

공통코드 구조와 변환 규칙은 `20261030000000_common_code_cleanup` migration을 기준으로 합니다. 실제 DB 적용 이력과 데이터 점검 결과는 비공개 운영 기록에서 관리합니다.

| 그룹           | 코드                                                                                                  | 화면 이름                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| INQUIRY_TYPE   | BUG_REPORT, GENERAL                                                                                   | 버그 제보, 일반 문의                                                                                               |
| INQUIRY_STATUS | PENDING, RECEIVED, IN_PROGRESS, RESOLVED, CLOSED                                                      | 대기, 접수, 처리 중, 처리 완료, 종료                                                                               |
| PROJECT_ORIGIN | PERSONAL, EDUCATION, COMPANY                                                                          | 개인, 교육, 회사                                                                                                   |
| PROJECT_TYPE   | UNSPECIFIED, WEB, HYBRID_APP                                                                          | 미지정, 웹, 하이브리드 앱                                                                                          |
| POST_CATEGORY  | NOTICE, DEV_LOG, AI, TECH, ISSUE, ENTERTAINMENT, CAREER, FINANCE, REAL_ESTATE, TROUBLESHOOTING, OTHER | 공지사항, 개발일지, AI 정보, IT·기술, 실시간 이슈, 연예·문화, 채용·커리어, 주식·금융, 부동산, 장애·이슈 해결, 기타 |

## 기준

- 식별 코드는 의미 있는 대문자 영문과 밑줄을 사용한다. 표시명은 nameKo/nameEn에서 관리한다.
- PROJECT_ORIGIN은 작업 배경이다. 기존 이름을 유지하고 PROJECT_CATEGORY로 중복 생성하지 않는다.
- PROJECT_TYPE의 미지정은 UNSPECIFIED로 명시한다. 기존 NULL은 해당 코드로 바꾸고 신규 폼도 이 값을 사용한다.
- 전체는 조회 조건으로만 사용하며 DB 카테고리로 저장하지 않는다.
- POST_CATEGORY는 관리자와 공개 게시판에서 공통코드를 조회한다. 새 코드와 정렬 순서, 표시명 변경이 반영된다. 현재 저장된 비활성 카테고리는 편집 시 유지할 수 있지만 새로 선택할 수는 없다. 서버에서도 유효/활성 여부를 확인한다.
- Post.category는 코드만 저장하고 categoryGroup=POST_CATEGORY와 복합 외래키로 연결한다. 프로젝트·문의의 기존 복합 외래키도 유지한다.
- 한글 category가 포함된 기존 게시판 URL은 기본 분류에 한해 새 코드로 해석한다.
- 기존 게시글 분류를 변환할 때는 원래 의미를 보존하며 제목·본문을 추측해 다른 카테고리로 옮기지 않습니다.
- POST_SOURCE 등 사용처가 없는 그룹은 추가하지 않았다.
- 기술코드의 유사 명칭도 실제 참조와 의미를 확인하기 전에는 임의 병합하지 않습니다.

## 적용과 검증

변경 전 공통코드와 콘텐츠의 ID·분류 참조를 비공개 위치에 백업하고, 적용 후 기존 연결과 행 수를 대조합니다. 백업과 실제 데이터 스냅샷은 Git에 포함하지 않습니다.

의미 기반 문의 코드와 게시글 카테고리 외래키를 사용하는 앱은 해당 migration과 함께 전환해야 합니다. 이전 앱과 새 DB를 섞으면 문의 접수·게시글 저장이 실패할 수 있습니다. 백업과 점검 시간을 확보하고 migration 적용 후 호환되는 웹 이미지로 전환합니다. 최초 콘텐츠 이관 도구의 제약은 [콘텐츠 이관](19-콘텐츠-운영-이관.md)을 따릅니다.
