# 글 작성·수집·예약·배치

## 서로 다른 세 가지 축
| 축 | 값 |
|---|---|
| 콘텐츠 생성 | 직접 작성 / AI 초안 생성 |
| 작업 실행 | 수동 / 예약 / 여러 건 배치 |
| 게시 | 임시저장 / 검토 후 발행 / 예약 발행 / 자동 발행 |

초기 자동화는 AI 초안 저장 + 관리자 검토. 자동 발행은 관리자 명시 설정으로만 켠다. 외부 사이트에서 무단으로 전체 기사를 복제하지 않으며 허용된 API/RSS/원문 링크와 요약을 사용한다. 서비스별 접근 조건은 소스 도입 시 확인한다.

## 실행 구조
관리자 수동 실행도 HTTP 요청에서 긴 AI 호출을 끝까지 수행하지 않고 DB 작업을 등록한다.
DSM 작업 스케줄러가 1분 간격으로 일회성 jobs:tick을 실행하는 구성을 권장한다. 실제 장비 성능과 빈도에 따라 조정한다. 웹 프로세스의 setInterval, 방문 시 cron 실행 방식은 사용하지 않는다.
Next와 같은 저장소/서비스 코드를 이용하지만 작업 entrypoint는 분리한다. 별도의 Spring이나 Redis는 초기 필수가 아니다.

## 신뢰성
1. 예약 시각은 timezone과 함께 계산하고 occurrence_key를 고정한다. UNIQUE(job_id,occurrence_key)로 중복 enqueue 방지.
2. DB 트랜잭션에서 FOR UPDATE SKIP LOCKED 등으로 작업을 원자적으로 claim하고 lease/heartbeat를 기록한다.
3. 외부 API 호출 동안 DB 트랜잭션을 열어두지 않는다. 호출별 timeout, 응답 크기/토큰/비용 상한.
4. 실패는 지수 backoff + 제한 재시도(초기 3회 제안), 초과 시 FAILED와 관리자 확인. 인증 오류는 무한 재시도하지 않는다.
5. 재시작 시 만료 lease만 재획득. 처리 보장은 at-least-once이며 exactly-once라고 표현하지 않는다.
6. job_run별 output_post_id UNIQUE 등으로 게시물 중복 생성을 방지한다. 저장과 상태 변경은 하나의 트랜잭션.
7. 외부 호출 후 저장 전 장애는 API 비용 중복 가능. 공급자가 지원하면 idempotency key 적용, 아니면 기록과 예산 상한으로 통제.
8. 발행은 현재 DRAFT/SCHEDULED·검토 상태를 다시 검사하여 조건부 UPDATE. 사용자 수정 충돌 시 덮어쓰지 않고 재검토.
9. NAS 정지 중 놓친 작업은 전부 폭주 실행하지 않는다. 기본 최근 1회만 보충하고 오래된 뉴스는 SKIPPED. 예약 발행은 재시작 후 due 항목을 처리하되 지연 여부 기록.
10. 자동 게시 OFF, 작업 전체 일시중지, 중복 실행 방지, 실패 내역·수동 재실행 화면 제공.

## AI 보안과 표시
외부 본문의 지시로 프롬프트·도구·수집 URL·권한을 변경하지 않는다. 모델은 DB/쉘/배포 도구에 접근하지 않는다. 구조화된 출력의 제목·본문·출처를 검증하고 Markdown을 안전하게 렌더한다. 출처가 없는 수치나 내용을 사실처럼 보완하지 않는다.
표시: AI 활용 여부, 검토 상태, 작성/갱신 시각, 원문 출처. 채용 마감일·시세·날짜 등 시간 의존 정보는 생성 시점과 출처를 기록한다.
