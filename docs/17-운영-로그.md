# 운영 로그

## 기록 범위

API 핸들러의 시작·완료, 서버 발급 requestId, 고정 route, method, status, durationMs를 JSON 한 줄로 기록합니다. 응답의 X-Request-Id로 같은 요청의 SQL과 오류를 찾습니다. 관리자 확인 이후 사용자 ID를 기록하며 그전에는 anonymous입니다. 정적 파일·페이지 전체 접근 로그는 아닙니다.

공통 pg Pool 쿼리는 종류와 원문 해시로 만든 sqlId, 처리시간, 성공 여부를 기록합니다. 1초 이상은 warn, 실패는 error입니다. SQL 원문·파라미터·요청 본문·쿼리스트링·쿠키·헤더·토큰·IP는 기록하지 않습니다. 오류는 작업명, 안전한 코드, 종류, 호출 위치만 남기며 원문 메시지와 DB detail은 제외합니다. 관리자 변경은 사용자 ID·대상 ID·작업을 기록합니다. 변조 방지 감사 저장소는 아닙니다.

## 보관과 제한

- 표준 출력과 LOG_ROOT 아래 날짜별 파일에 함께 기록합니다. LOG_ROOT가 없으면 표준 출력만 사용합니다.
- 파일은 연도/월/oz_YYYY-MM-DD.jsonl 형식이며 파일 날짜와 로그 시각은 UTC입니다.
- 30일 지난 날짜 파일은 그날 첫 기록 시 정리합니다. 요청이 없으면 다음 기록 때 정리합니다.
- 파일 크기 자체 제한은 없으므로 저장소 여유 공간과 접근 권한을 확인합니다.
- 기록 실패는 log.file_write_failed, 대기 1,000건 이상은 log.file_queue_full을 표준 오류에 알립니다. API는 계속 처리하며 강제 종료 시 대기 중 파일 로그 일부가 유실될 수 있습니다.
- Next.js 자체 시작·프레임워크 로그는 컨테이너 로그에서 확인합니다.

## 배포 설정

컨테이너의 LOG_ROOT와 영속 로그 볼륨을 함께 설정합니다. 다음은 컨테이너 내부 경로 예시이며, 실제 호스트 경로는 비공개 배포 설정에서 지정합니다.

```text
-e LOG_ROOT=/app/logs
-v HOST_LOG_DIRECTORY:/app/logs
--log-driver local --log-opt max-size=10m --log-opt max-file=3
```

HOST_LOG_DIRECTORY는 실제 절대 경로로 바꿉니다. 웹 실행 사용자에게 필요한 쓰기 권한만 부여하고 컨테이너 교체 후에도 같은 볼륨을 연결합니다. 개발 로그는 운영 로그와 별도 디렉터리를 사용합니다.

배포 후 요청 ID, 사용자 ID, SQL ID와 변경 대상 ID의 기록 여부를 확인합니다. 실제 로그와 조회 결과는 Git·공개 게시글·첨부에 올리지 않습니다. 환경별 주소·공유 폴더·파일 이전 내역은 비공개 운영 기록으로 관리합니다.

파일 저장소 위치를 변경할 때는 기존 파일을 보존하고 이동 결과와 권한을 확인한 뒤 STORAGE_ROOT를 변경합니다. DB의 상대 저장 키와 원본 파일의 대응을 유지하고, 기존 이미지 읽기와 신규 업로드를 검증합니다.
