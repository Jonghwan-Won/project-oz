# 운영 로그

구현한 API 핸들러의 시작/완료, 서버 발급 requestId, 고정 route, method, status, durationMs를 JSON 한 줄로 기록한다. 응답 X-Request-Id로 같은 요청의 SQL과 오류를 검색한다. 관리자 확인 이후부터 사용자 ID가 기록되고 이전에는 anonymous다. 정적 파일/페이지 전체 접근 로그는 아니다.

공통 pg Pool 쿼리는 종류와 원문 해시로 만든 sqlId, 처리시간, 성공 여부를 기록한다. 1초 이상은 warn, 실패는 error다. SQL 원문/파라미터, 요청 본문, 쿼리스트링, 쿠키/헤더/토큰, IP는 기록하지 않는다. 오류는 작업명, 안전한 코드, 종류, 호출 위치만 기록하며 원문 메시지/DB detail은 제외한다. 관리자 변경은 사용자 ID와 대상 ID, 작업을 남긴다. 변조 방지 감사 저장소는 아니다.

## 보관

표준 출력과 LOG_ROOT 아래 날짜 파일에 함께 기록한다. LOG_ROOT가 없으면 표준 출력만 쓴다.

- 운영: logs/2026/10/oz_2026-10-30.jsonl
- 개발: logs-dev/2026/10/oz_2026-10-30.jsonl
- 파일 날짜/로그 시각은 UTC. 날짜가 바뀌면 새 파일에 기록한다.
- 30일 지난 날짜 파일은 그날 첫 기록 시 삭제한다. 요청이 없으면 다음 기록 때 정리한다.
- 파일 크기 자체 제한은 없으므로 NAS 여유 공간을 확인한다.
- 기록 실패는 log.file_write_failed, 대기 1,000건 이상이면 log.file_queue_full을 Docker 로그에 알린다. API는 계속 처리된다. 강제 종료 시 대기 중 파일 로그 일부는 유실될 수 있다.
- Next.js 자체 시작/프레임워크 로그는 Docker 로그에만 남는다.

```sh
sudo docker logs --timestamps --tail 100 -f project-oz-web
sudo tail -f /volume1/docker/project-oz/logs/2026/10/oz_2026-10-30.jsonl
sudo grep '요청-ID' /volume1/docker/project-oz/logs/2026/10/oz_2026-10-30.jsonl
```

## 운영 배포

NAS SSH에서 준비한다.

```sh
sudo mkdir -p /volume1/docker/project-oz/logs
sudo chown 1000:1000 /volume1/docker/project-oz/logs
sudo chmod 750 /volume1/docker/project-oz/logs
```

새 이미지 웹 컨테이너 생성 시 기존 옵션에 아래 옵션을 추가한다. DB migration은 없다. Docker 로그도 10MB 파일 최대 3개로 제한한다. NAS logs 볼륨은 컨테이너 교체 후 유지된다.

```text
-e LOG_ROOT=/app/logs
-v /volume1/docker/project-oz/logs:/app/logs
--log-driver local --log-opt max-size=10m --log-opt max-file=3
```

배포 후 로그인, 업로드, 글 저장을 수행하고 파일에 requestId/userId/sqlId/변경 대상 ID가 남는지 확인한다. 기존 컨테이너에는 새 로깅 코드가 없으므로 이미지 재배포가 필요하다.

## 개발 파일 경로 이전

uploads/dev 대신 uploads-dev를 쓰면 운영/개발 폴더와 백업 범위가 명확해진다. DB에는 상대 storageKey만 있으므로 DB 변경은 없다. 개발 서버를 종료한 상태에서 NAS SSH로 확인한다.

```sh
sudo ls -ld /volume1/docker/project-oz/uploads/dev
sudo ls -ld /volume1/docker/project-oz/uploads-dev
```

대상이 이미 있으면 멈추고 내용을 비교한다. uploads-dev가 없고 uploads/dev가 있을 때만 이동한다. -n으로 덮어쓰기를 막는다.

```sh
sudo mv -n /volume1/docker/project-oz/uploads/dev /volume1/docker/project-oz/uploads-dev
sudo ls -la /volume1/docker/project-oz/uploads-dev
```

이동 성공 후 PC .env.local의 STORAGE_ROOT를 바꾸고 LOG_ROOT를 추가한다. 아래는 dotenv의 큰따옴표 값이며 역슬래시는 그대로 작성한다.

```dotenv
STORAGE_ROOT="\\100.124.18.71\docker\project-oz\uploads-dev"
LOG_ROOT="\\100.124.18.71\docker\project-oz\logs-dev"
```

개발 logs-dev는 NAS 접속 계정의 쓰기 권한이 필요하다. 개발 서버 재시작 후 기존 이미지 조회와 신규 업로드를 확인한다. 실제 파일 이동 전에 환경변수만 바꾸면 기존 이미지가 보이지 않는다. 운영 uploads와 마운트는 그대로 둔다.
