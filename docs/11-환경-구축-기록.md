# 개발·운영 환경 구성

이 문서는 공개 가능한 환경 구성과 선택 이유를 설명합니다. 실제 호스트 주소, 장비 모델·관리 소프트웨어 버전, 계정명, 볼륨·백업 위치, 장애 대응 내역은 공개 저장소에서 관리하지 않습니다. 배포 절차는 [배포·운영](06-배포-운영.md)을 따릅니다.

## 구성

- 공개 접속: 브라우저 → HTTPS 진입점(Cloudflare Tunnel) → Next.js 웹 컨테이너
- 데이터: 웹 컨테이너 → 운영 PostgreSQL 및 영속 파일 저장소
- 개발: 로컬 Next.js → SSH 터널 → 별도 개발 PostgreSQL
- 배포: GitHub Actions → Docker 이미지 검사 → GHCR → 운영자가 컨테이너 교체

DB와 관리 접속은 인터넷에 직접 공개하지 않습니다. 외부 개발 접속에는 접근이 제한된 사설 연결과 SSH 터널을 사용합니다. 실제 접속 정보는 환경별 비공개 설정으로 관리합니다.

## 선택 이유

### 개발·운영 데이터 분리

소스와 개발 서버는 각 개발 PC에서 실행하고, 개발 DB는 별도 환경을 사용합니다. 운영과 개발의 DB·계정·파일 저장소를 분리해 개발 변경이 운영 데이터에 영향을 주지 않게 합니다. 같은 호스트의 폴더 분리는 네트워크 격리나 별도 백업을 대신하지 않습니다.

### CI에서 빌드하고 서버에서 실행

GitHub Actions가 Dockerfile로 이미지를 만들고 검사하며, 운영 호스트는 완성된 이미지를 실행합니다. 운영 호스트에 빌드 부하를 더하지 않고 커밋 SHA로 배포 버전을 식별하기 위한 구성입니다. 호스트별 성능 비교 결과를 뜻하지 않습니다.

### 이미지와 데이터 분리

업로드 파일과 DB는 컨테이너 교체와 독립적으로 유지합니다. 웹과 migration 이미지는 같은 커밋 SHA로 맞추고, 환경변수는 실행 시 주입합니다. 비밀값이나 백업을 이미지에 포함하지 않습니다.

## 환경별 준비

로컬 설정과 SSH 터널은 Git으로 동기화되지 않습니다. 각 PC에서 개발용 환경변수와 저장소 권한을 준비해야 합니다. 운영 OAuth 키를 개발에 복사하지 않습니다. 상세 설정은 [로컬 개발](05-로컬-개발.md)을 참고하세요.

운영은 DB와 업로드를 함께 백업하고 실제 복원을 검증해야 합니다. 소스나 과거 배포 성공만으로 현재 서버 상태를 보증하지 않습니다. 구현 범위와 남은 검증은 [현재 구현 상태](10-현재-구현-상태.md)를 따릅니다.
