# 공개 화면과 관리자 권한

현재 접근 정책입니다. 운영 배포 후에는 로그인과 권한별 접근을 별도로 검증해야 합니다.

## 접근 범위

| 영역                           | 비관리자 방문자                                                                               | 지정 관리자                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------ |
| 관리자 대시보드                | 동일한 카드와 실제 집계 수치 표시, 대기 문의 확인 버튼 비활성화                               | 전체 현황·문의·미사용 파일 통계      |
| 프로젝트·게시글 관리           | 동일한 목록·검색·상세 UI, 입력·에디터·업로드·등록·저장·삭제 비활성화, 미리보기 가능           | 비공개 포함 조회·등록·수정·논리 삭제 |
| 공통코드·문의                  | 메뉴 표시하되 비활성화, 직접 접근은 로그인 화면으로 이동                                      | 조회 및 기존 관리 기능               |
| 첨부파일 관리                  | 동일한 목록·검색 UI로 미사용 포함 파일명 외 메타데이터 조회, 다운로드·출처 링크·삭제 비활성화 | 전체 조회 및 기존 관리 기능          |
| 파일 다운로드                  | 공개 콘텐츠에 연결된 파일만                                                                   | 비공개·미사용 파일 포함              |
| 실험실·공통 UI 가이드          | 공개, 예제 및 로컬 파일 체험                                                                  | 동일                                 |
| 내부 Markdown 문서·환경 구조도 | 비공개                                                                                        | 조회 가능                            |
| DB 진단 API                    | 접근 불가                                                                                     | 개발 환경에서만 가능                 |

관리자 여부는 매 요청의 DB 세션과 GitHub 고유 ID(`GITHUB_ADMIN_ID`)로 판정한다. 화면뿐 아니라 관리자 조회 서비스와 변경 API, 파일 업로드·다운로드에도 적용한다. 변경 요청은 BETTER_AUTH_URL에 설정한 공개 Origin과 일치해야 한다. Origin 또는 BETTER_AUTH_URL이 없거나 유효하지 않으면 거절한다. 비로그인 문의 접수는 그대로 허용한다. 공개 관리자 화면은 기존 관리 컴포넌트를 읽기 전용으로 재사용하고 서버 조회에 공개 범위를 적용하며 비공개 콘텐츠·문의 본문은 응답에 포함하지 않는다. 첨부파일 목록은 미사용을 포함한 용량·등록일·사용 여부를 공개한다. 비관리자 응답의 원본 파일명은 고정 문구로 대체하고 DB에서 읽지 않으며, 파일명 검색도 적용하지 않아 검색 결과로 이름을 추측하지 못하게 한다. 연결 콘텐츠 제목과 ID도 제거한다. 실제 파일 읽기는 기존 공개 콘텐츠 연결 여부 및 관리자 권한 검사로 보호한다. 예외로 `/api/portfolio-files/{resume|portfolio}`는 서버 환경 변수(`PORTFOLIO_RESUME_ASSET_ID`, `PORTFOLIO_DOCUMENT_ASSET_ID`)에 지정한 PDF 한 개씩만 비로그인으로 내려준다. 요청은 종류 이름만 받고 파일 ID는 받지 않으며, 지정되지 않았거나 PDF가 아니면 404를 반환한다. 대시보드의 전체/미노출 건수·대기 문의 건수·미사용 파일 개수 및 용량은 공개 집계로 제공한다.

로그인은 GITHUB_ADMIN_ID로 지정한 GitHub 고유 계정만 허용한다. 공급자 프로필 확인 시 다른 계정은 거절한다. 성공 후 메인으로 이동하며 헤더의 세션 상태에 따라 로그인/로그아웃을 표시한다. 로그아웃 후 현재 서버 화면도 새로 조회한다.

## 운영 반영 순서

1. 운영 DB를 백업하고 인증 테이블을 포함한 migration을 적용한다(`npm run db:migrate:deploy`).
2. 운영 GitHub OAuth 앱에 실제 HTTPS 사이트 주소와 `/api/auth/callback/github`를 등록한다. 개발 OAuth 앱과 분리한다.
3. 운영 런타임에 DATABASE_URL, STORAGE_ROOT, BETTER_AUTH_URL, BETTER_AUTH_SECRET, GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET, GITHUB_ADMIN_ID를 설정한다. 비밀값은 저장소에 넣지 않는다.
4. 앱을 배포하고 비로그인·일반 계정·관리자별 공개 목록, 직접 URL, 쓰기 API, 비공개 파일 차단을 확인한다.
5. 관리자로 테스트 데이터를 등록·수정·삭제하고 파일 저장소 권한 및 로그아웃 후 차단을 확인한다.

기존 개발 환경·oz_dev·loopback 제한은 서버 관리자 세션 검사로 대체했다. 운영 DB와 파일 저장소를 설정하면 실제 데이터가 변경되므로 개발 설정을 그대로 복사하지 않는다. 배포 후 권한별 검증은 별도로 수행한다.

## 후속 접근 정책

관리자 페이지 전체를 지정 관리자 로그인 후에만 접근하도록 전환할 예정이다. 현재 공개 미리보기는 유지하며 이 문서의 제한을 적용한다. 로그인 허용 계정은 GITHUB_ADMIN_ID로 지정한 단일 GitHub 계정이고, 임의의 GitHub 로그인 사용자를 관리자로 인정하지 않는다.
