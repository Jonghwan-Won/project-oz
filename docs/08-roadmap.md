# 구현 순서와 인수 기준

## 1. 실행 뼈대
Next App Router/TypeScript, 공통 스타일, 공개/관리자 레이아웃, 개발 DB, 환경 검증, CI typecheck/test/build, Docker runtime 작성.
완료: 새 PC에서 README대로 실행, 360/390/768/1280px 가로 넘침 없음, 모바일 메뉴·키보드 동작.

## 2. 인증·권한
인증 공급자와 라이브러리 고정, DB 세션, ADMIN/MEMBER, 서버 권한 함수, 관리자 bootstrap, 감사 로그.
완료: 비로그인·회원의 직접 관리자 API 호출 거부, 역할 회수 반영, 운영에 데모 로그인 없음.

## 3. 실제 콘텐츠
메뉴/카테고리, 게시판 전체/분류/상세, 관리자 작성/수정/발행, 프로젝트/실험실 상태 전환, 소개.
완료: DB 영속 저장, 비공개/예약 글 숨김, 공개 취소 캐시 제거, 상세 URL 유지, XSS 차단.

## 4. 도움·문의
FAQ·연락 안내, 본인 문의 등록/목록/상세, 관리자 답변, 상태 관리. 첨부는 보안 업로드 구현 후 추가.
완료: 다른 회원 문의·첨부 조회 거부, 입력 길이/속도 제한, 개인 정보 로그 미노출.

## 5. 첫 NAS 배포
도메인/TLS, runtime/DB 볼륨, 수동 release 절차, 백업/복원, healthcheck.
완료: 브라우저 실기기 확인, 컨테이너 교체 후 데이터 유지, DB 포트 비공개, 백업으로 별도 DB 복원 성공.

## 6. 예약과 AI
예약 발행 먼저 → 수동 AI 생성 → 예약 AI 생성 → 필요시 배치. 자동 발행은 별도 설정으로 도입.
완료: 동시 실행에도 동일 occurrence 중복 게시 없음, 재시작/lease 만료/외부 timeout/비용 제한/지연 실행 테스트 통과.

## 보류 항목
Spring, 공개 댓글·회원 게시글, 앱 API, Redis, 전문 검색 엔진, 이메일 발송, 대규모 파일 업로드, 자동 배포는 첫 구현 범위에서 보류한다. 사용자 요구인 자동화·관리자 자체를 삭제하지 않는다.

create-next-app 기반 저장소 생성 후 1~2단계까지 먼저 구현한다. 인증 도구·Node/Next/PostgreSQL/Prisma 버전을 확인하여 docs/09-decisions.md에 고정한다. 이후 UI 초안을 컴포넌트로 옮기고 실제 DB 데이터로 대체한다.
