# 프로젝트 데이터 구성

현재 스키마와 변경 이력은 prisma/schema.prisma와 prisma/migrations/가 기준입니다. 이 문서는 공개 가능한 데이터 구조와 초기 데이터의 역할을 설명합니다. 실제 DB 적용 일지, 계정, 백업 위치와 데이터 스냅샷은 저장소에 포함하지 않습니다.

## 데이터 구조

- Project에 작업 구분·유형·공개 여부·기간·버전을 저장합니다.
- ProjectTranslation에 ko/en 제목·요약·본문과 본문 스키마 버전을 저장합니다. 영어가 없으면 한국어로 대체합니다.
- ProjectTag와 Tag로 기술·주제 태그를 연결합니다.
- ProjectAsset과 Asset으로 대표 이미지·본문 이미지·첨부파일을 연결합니다. 원본은 별도 파일 저장소에 두고 DB에는 상대 저장 키를 기록합니다.
- 공통코드의 복합 외래키와 DB 제약으로 잘못된 분류 참조를 막습니다. 세부 제약은 migration SQL을 확인합니다.

## 공개 조회와 초기 데이터

홈·프로젝트 목록·상세는 src/server/services/projects.ts에서 DB를 조회합니다. 노출되고 삭제되지 않은 프로젝트만 반환하며 DB 조회 실패 시 TS 데이터로 대체하지 않습니다.

src/content/projects.ts와 언어 사전의 프로젝트 항목은 초기 seed 자료입니다. 운영 DB의 수정 사항이 이 파일에 자동 반영되지는 않습니다. 초기 데이터에도 고객사명과 프로젝트 개요·기간이 포함돼 있으므로 공개 가능한 내용만 유지합니다.

seed는 트랜잭션으로 실행하고 기존 slug와 코드를 덮어쓰지 않습니다. 초기 데이터 재실행으로 기존 콘텐츠를 갱신하지 않습니다. 미제공 기간·역할·이미지나 작성자를 임의로 만들지 않습니다.

## 변경과 검증

- 이미 적용된 migration은 수정하지 않고 새 migration을 추가합니다.
- 수정은 version 확인과 행 잠금·트랜잭션으로 충돌을 검사합니다. 삭제는 논리 삭제이며 원본 파일은 자동 삭제하지 않습니다.
- 공개 프로젝트 조회·상세·첨부 읽기에서 공개 여부와 삭제 상태를 함께 확인합니다.
- 스키마·seed 검사는 별도 개발 DB에서 수행합니다. npm run db:test는 고유한 임시 스키마를 생성해 검사하고 제거하므로 운영 DB에서 실행하지 않습니다.
- 운영 적용 전 DB와 파일을 함께 백업하고 migration과 앱의 호환성을 확인합니다. 실제 환경별 적용 결과는 비공개 운영 기록으로 관리합니다.
