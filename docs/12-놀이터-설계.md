# 코드·DB 놀이터 설계 초안

미구현 아이디어의 설계 초안입니다. 운영 서버에 코드 실행이나 임의 DB 쿼리 기능이 제공된다는 뜻이 아닙니다.

사용자 요청: 언어를 선택해 코드를 입력하고 실행 결과를 확인하는 화면과 DB 실험 공간. 이번 작업에서는 설계만 정리하며 실행 기능이나 DB 권한을 추가하지 않는다.

## 화면 구성

가이드 아래 하나의 놀이터 화면에서 코드와 DB 탭을 나눈다. 언어 선택 → 예제 불러오기 → 코드 입력 → 실행/중지 → 결과 확인 순서로 사용한다. 출력과 오류를 구분하고 초기화 버튼을 둔다. React·Vue에는 콘솔 외에 화면 미리보기가 필요하다. 편집기는 우선 일반 textarea로 시작하고 실제 편집 수요가 생기면 전용 코드 에디터를 검토한다.

## 언어별 실행 방식과 도입 순서

| 단계 | 대상 | 실행 방식 | 처음 제공할 범위 |
| --- | --- | --- | --- |
| 1 | JavaScript | 브라우저의 분리된 실행 환경 | console 출력, 오류, 중지·시간 제한 |
| 2 | TypeScript | JS 변환 후 같은 분리 환경에서 실행 | 기본 TS 문법과 컴파일 진단, 타입 검사 제공 여부를 명확히 표시 |
| 3 | React | JSX/TSX 변환과 별도 렌더링 공간 | 화면 미리보기와 콘솔, 고정된 React 버전 |
| 4 | Vue | 템플릿/컴포넌트 변환과 별도 렌더링 공간 | 화면 미리보기와 콘솔, 고정된 Vue 버전 |
| 별도 준비 | Java | 웹 프로세스와 분리한 실행 전용 환경 | 컴파일·표준 출력·컴파일/실행 오류 |

JS/TS 예제:

```js
let test = '껄껄';
console.log('이렇게 하면 되는건가 ?? ', test);
```

기대 출력은 메시지와 `껄껄`을 함께 표시하는 것이다. console 여러 인자, undefined, 순환 참조 같은 값도 출력 과정에서 실행기를 깨뜨리지 않도록 처리한다. JS 실행, TS 문법 변환, TS 타입 검사, 프레임워크 화면 빌드는 서로 다른 작업이므로 단순 실행을 모두 빌드 성공이라고 표시하지 않는다.

## 코드 실행의 경계

- Next.js 서버에서 입력 코드를 eval하거나 임의 쉘 명령으로 실행하지 않는다.
- 초기 JS/TS는 웹앱 본문과 분리된 브라우저 실행 환경을 사용한다. UI를 멈추는 무한 루프를 종료할 수 있는 실행 단위와 시간 제한이 필요하다. 일반 iframe만으로 CPU 격리나 모든 네트워크 차단이 보장된다고 가정하지 않는다.
- 프레임워크 미리보기는 샌드박스 문서와 제한된 통신으로 구성한다. 부모 페이지 DOM·쿠키·저장소 접근을 허용하지 않는다. 메시지는 실행별 식별자와 발신 실행 환경을 검증하고 출력 크기·개수를 제한한다.
- npm 패키지 설치, 임의 모듈 다운로드, 외부 네트워크, 파일 접근은 초기 범위에서 제공하지 않는다. 필요한 런타임은 고정된 빌드 산출물로 준비한다.
- Java는 NAS 운영 웹·운영 DB와 분리한 실행기에서 CPU·메모리·프로세스·시간·출력·파일·네트워크 권한을 제한해야 한다. Docker 실행만으로 신뢰할 수 없는 코드의 보안 격리가 완성됐다고 보지 않는다. 비용과 장비 자원을 확인한 뒤 도입 여부를 결정한다.

## DB 놀이터

첫 버전은 실제 연결 상태와 미리 준비한 SELECT 예제만 확인하도록 시작한다. 자유 SQL 입력과 쓰기 실험은 후속 단계다.

| 대상 | 허용 범위 |
| --- | --- |
| 운영 DB | 놀이터 연결 대상에서 제외 |
| 현재 공용 개발 DB | 상태 확인과 사전에 정한 조회만 검토 |
| 자유 SQL·쓰기 실험 | 별도 실험 DB/스키마와 가짜 데이터로 준비 |

- 브라우저가 접속 URL이나 비밀번호를 보내지 않는다. 서버가 정해진 실험 환경만 선택한다.
- 개발 전용 라우트의 서버 검사와 입력 검증을 적용한다. 향후 공개 시 인증·권한·실행 제한을 먼저 갖춘다.
- 읽기 전용 계정 권한과 DB 수준의 실행 제약을 사용한다. `SELECT로 시작하는가` 같은 문자열 검사만으로 안전을 보장하지 않는다.
- 연결·쿼리 제한 시간, 반환 행·응답 크기·동시 실행 수를 제한한다. 원본 접속 정보나 내부 오류는 클라이언트에 그대로 전달하지 않는다.
- 쓰기 실험의 초기화는 전용 실험 데이터에만 적용하고 공용 개발·운영 데이터를 지우지 않는다. 트랜잭션 rollback만으로 모든 SQL 부작용이 사라진다고 가정하지 않는다.

## 구현 전에 확정할 것

JS/TS 우선 여부, React/Vue에서 허용할 파일·패키지 범위, 출력/시간 상한, Java 실행기 위치, 전용 실험 DB 준비와 초기화 권한을 정한다. 현재는 개발 전용 설계이며 NAS 운영에 실행 엔드포인트를 추가하지 않는다.
