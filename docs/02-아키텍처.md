# 아키텍처

## 현재 요청 구조

```text
브라우저 → HTTPS 역방향 프록시 → Next.js standalone 서버
                                  ├─ PostgreSQL (앱 데이터·세션)
                                  └─ 영속 파일 경로 (첨부 파일)
```

Next.js App Router가 페이지 렌더링, Route Handler, 서버 서비스, 인증 및 DB 접근을 한 애플리케이션으로 제공합니다. 운영 배포는 웹 이미지와 DB/업로드 데이터를 분리합니다. CI는 이미지 빌드와 게시를 수행하고 NAS 반영은 수동입니다.

## 코드 경계

- 공개·관리 페이지는 `src/app/`, 재사용 UI는 `src/components/`, 공통 입력/데이터 처리는 `src/lib/`, 서버 전용 권한·DB 처리는 `src/server/`에 둡니다.
- HTTP 경계는 `src/app/api/`의 Route Handler입니다. 요청값은 서버에서 검증하고 인증·권한을 확인합니다.
- Prisma 모델/마이그레이션은 `prisma/`, 공유 타입/클라이언트 생성물은 `src/generated/prisma/`에 있습니다.
- 운영 DB·세션·파일 응답을 정적 공개 캐시에 넣지 않습니다. 공개 여부는 서버 조회에서 판정합니다.

실제 폴더가 이 문서와 다를 경우 현재 저장소 구조와 코드를 기준으로 합니다. 미구현 구조를 미리 만들지 않습니다.

## 운영 원칙

- DB 접근은 Next 서버에서만 수행하고 비밀값을 브라우저 번들에 전달하지 않습니다.
- 세션 검사와 권한 검사는 UI 표시와 별개로 서비스/API 경계에서 수행합니다.
- 웹 런타임은 비 root로 실행하고 DB 포트는 인터넷에 공개하지 않습니다.
- migration은 앱 기동과 분리된 명시적 배포 단계로 실행합니다.
- 예약/AI 작업 실행기는 아직 없습니다. 향후 필요성과 격리 방식을 확정한 뒤 설계합니다.
