# 에디터와 파일

## 에디터

프로젝트와 게시글 본문은 공통 Tiptap 에디터가 JSON 문서로 저장·렌더링합니다. 서버는 저장 전에 문서 구조와 허용된 서식을 검증하고 HTML/스크립트를 실행하지 않습니다. 이미지 본문 참조는 업로드된 사이트 파일 ID를 사용하며 외부 이미지 URL이나 base64 본문은 허용하지 않습니다.

툴바·표·색상·서식의 사용법은 [공통 UI 문서](../src/components/ui/README.md)를 참고하세요.

## 파일 저장과 접근

- 허용 형식은 PNG/JPEG/WebP/PDF, 최대 크기는 10 MB입니다. 서버에서 요청 크기와 파일 형식 시그니처를 확인하고 UUID 기반 저장 키를 사용합니다.
- 파일 원본은 `STORAGE_ROOT` 아래에 저장하고 DB에는 상대 `storageKey`와 메타데이터를 기록합니다. 컨테이너 재생성 후에도 유지되도록 영속 볼륨으로 연결해야 합니다.
- 업로드 및 관리자 전용 파일 접근은 지정 관리자 세션과 동일 Origin 검사를 거칩니다.
- 방문자는 공개되고 삭제되지 않은 프로젝트/게시글에 연결된 파일만 읽습니다. 비공개·미사용 파일은 관리자만 읽을 수 있습니다.
- 비로그인 관리자 미리보기에서는 원본 파일명을 서버 조회부터 숨기고 파일명 검색을 적용하지 않습니다.
- PDF는 첨부 다운로드로 제공하고, 이미지 응답에는 `nosniff`, sandbox CSP, 비공개 no-store 캐시 제어를 적용합니다.
- 저장되지 않은 편집에서 참조를 제거한 파일은 미사용 파일이 될 수 있습니다. 미사용 정리는 DB에 저장된 연결을 기준으로 하므로 편집 중인 내용을 먼저 저장하거나 닫아야 합니다.

파일 목록의 사용 여부와 연결 수는 DB 관계 기준이며 NAS 폴더를 전수 검사한 값이 아닙니다. 수동 파일 삭제는 DB와 참조를 고아 상태로 만들 수 있습니다.

## 운영 준비

운영 코드는 인증·권한 검사를 지원하지만, `STORAGE_ROOT`의 운영 볼륨 마운트와 백업은 운영자가 배포 환경에서 준비해야 합니다. DB 백업과 업로드 백업을 함께 유지하고 복원도 함께 검증하세요. 운영 적용 절차는 [배포·운영](06-배포-운영.md)을 참고합니다.
