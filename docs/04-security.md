# 인증·권한·보안 기준

2026-10-29 구현 기준: GitHub OAuth와 DB 세션을 사용하며 GITHUB_ADMIN_ID로 지정한 단일 계정만 관리자로 판정한다. 공개 관리자 미리보기는 공개 콘텐츠만 조회하고 내부 조회·변경은 서버 권한 검사로 보호한다. 일반 계정 로그인은 관리 권한을 부여하지 않는다. 문의 접수는 비로그인도 가능하다. 아래 기능별 permission·다중 관리자·계정 정지 등은 설계 방향이며 현재 구현된 기능을 뜻하지 않는다. 현재 접근 범위와 운영 반영 절차는 [공개 범위와 관리자 권한](16-public-access-plan.md)을 따른다.

## 인증
- 초기에는 검증된 인증 라이브러리와 OAuth/OIDC 공급자 1개, DB 세션 방식을 권장한다. 정확한 라이브러리·공급자 선택은 구현 전 확정한다.
- 비밀번호 인증은 직접 구현하지 않는다. 필요해지면 라이브러리의 해싱·메일 검증·재설정·잠금 정책을 적용한다.
- 최초 관리자는 서버의 별도 운영 절차에서 공급자의 고유 subject로 지정한다. 첫 가입자 자동 관리자, 브라우저 role 전송, 미검증 이메일 매칭을 금지한다.
- 운영 쿠키: Secure, HttpOnly, 적절한 SameSite 및 좁은 Domain/Path. 로컬 개발 예외는 환경으로 한정한다.
- 로그아웃·계정 정지·권한 변경 시 DB 세션 폐기 또는 즉시 재검증. 관리자는 공급자 MFA 사용을 기본 운영 조건으로 한다.

## 기본 권한표
| 동작 | 비로그인 | 회원 | 관리자 |
|---|---|---|---|
| 공개 콘텐츠/FAQ | 허용 | 허용 | 허용 |
| 문의 작성 | 거부 | 허용 | 허용 |
| 문의 내용/첨부 | 거부 | 본인 것만 | inquiry.manage |
| 게시글 작성/수정/발행 | 거부 | 거부 | 해당 permission |
| 메뉴/권한/자동화 관리 | 거부 | 거부 | 해당 permission |

초기 ADMIN은 모든 운영 권한을 가진다. 기능별 permission은 서버의 고정 목록으로 정의하고 역할에 연결한다. 공용 라우트는 명시 허용, 나머지는 기본 거부한다. 마지막 활성 관리자 제거는 막는다.
공통 함수 예: requireSession(), requirePermission(code), assertInquiryOwnerOrManager(id). middleware/proxy는 빠른 이동 제어 보조 수단이다. Action·Handler·서비스/데이터 조회 경계가 최종 검사 위치다. UUID 사용은 소유권 검사를 대신하지 않는다.

## 필수 통제
1. 입력: Zod 등 서버 스키마로 길이·타입·enum·URL 검사. ID를 바꾼 직접 API 호출도 검사.
2. XSS: Markdown raw HTML 비활성화, 링크 http/https만 허용, 렌더 결과 정화. 임의 MDX/JS 실행 금지.
3. SQL: 파라미터화 ORM 사용. raw SQL 필요 시 바인딩, 문자열 결합 금지.
4. CSRF: 선택한 인증 라이브러리와 Next의 보호 기능을 유지하고 cookie-auth 변경 요청에서 Origin 검증/필요한 CSRF 토큰 적용. GET으로 변경하지 않는다. 프록시 forwarded host 신뢰 범위 고정.
5. 캐시: 관리자·계정·문의·초안 응답 no-store/private. 개인정보를 정적 생성·공용 CDN 캐시에 넣지 않는다. 공개 취소 시 캐시 무효화.
6. 비밀: DB/AI/OAuth 키는 서버 환경에만. NEXT_PUBLIC_ 변수에 비밀 금지. 운영 .env와 키를 이미지/레지스트리에 포함하지 않는다.
7. 남용: 로그인·문의·AI 실행·업로드에 속도/용량 제한. 인증된 사용자별 제한과 프록시 IP 제한 결합. 임의 X-Forwarded-For 신뢰 금지. 다중 인스턴스 시 DB 등 공유 상태 필요.
8. 헤더: HTTPS, CSP(nonce/hash 기반으로 Next 호환 검증), frame-ancestors, nosniff, Referrer-Policy. HSTS는 TLS·하위 도메인 검토 후 적용.
9. 업로드 도입 시: 크기·MIME·확장자·실제 형식 검사, 임의 UUID 이름, 경로 순회 방지. 초기 SVG/HTML 업로드 차단. 비공개 파일은 public/ 밖에 저장, 다운로드 인가. 악성 파일 검사/격리 정책을 도입한 뒤 문의 첨부 공개.
10. 외부 수집: 허용 출처 목록만 접근. localhost/사설망/link-local/클라우드 metadata 차단, IPv4/IPv6 및 DNS/redirect 재검증, 시간·응답크기 제한. 외부 내용은 지시가 아닌 데이터로 처리.
11. AI: 문의/계정정보/비밀을 전송하지 않음. 도구 실행 권한 없음. 모델 출력은 검증 후 초안 저장. 최대 토큰·비용·실행 횟수 제한. 자동 게시 기본 OFF.
12. 운영: 컨테이너 non-root, 최소 권한, Docker socket 미탑재. DB 외부 포트 비공개. 앱 DB 계정과 migration 계정 분리. 정기 의존성 점검 및 취약 버전 패치.

## 개인 정보와 기록
수집 정보는 계정 식별자·문의에 필요한 최소 항목으로 제한한다. 개인정보 안내에 보유 기간과 삭제 방법을 작성한다. 문의 종료 후 보관 기간, 계정 탈퇴, 백업 만료를 함께 확정한다. 제안: 일반 운영 로그 30일, 보안 감사 로그 90일, 문의 종료 후 1년; 법적 의무 판단이 아닌 운영 초안이다.

## 필수 검증 사례
- 비로그인/회원이 관리자 URL과 Action/Handler를 직접 호출하면 거부.
- 다른 회원의 inquiry ID/asset ID로 조회·수정 불가.
- 역할 회수 후 기존 세션으로 관리자 작업 불가.
- 비공개 프로젝트/예약글은 상세 URL·검색·캐시에서도 비노출.
- 악성 본문, javascript: 링크, 과대 입력, 위조 Origin, 반복 문의, 내부망 수집 URL 차단.
- 배포 이미지에 .env/키/DB dump가 없는지 확인.
