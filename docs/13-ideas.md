# OZ 아이디어 저장소

사용자가 제안한 아이디어를 잊지 않기 위한 목록이다. 등록은 구현·일정 확정을 뜻하지 않는다. 새 제안은 이 문서에 추가하고, 구체적인 설계나 구현이 생기면 연결 문서와 상태를 갱신한다. 상태는 아이디어 / 설계 초안 / 구현 중 / 완료 / 보류로 구분하며 사용자 요청 없이 우선순위나 일정을 확정하지 않는다.

나중에 **“OZ 아이디어 목록 보여줘”**, **“아직 구현하지 않은 OZ 아이디어 정리해줘”**, **“아이디어 저장소에서 마인드맵 아이디어 구체화해줘”**라고 요청하면 이 문서를 기준으로 정리한다. 다른 PC나 새 대화에서도 이 프로젝트 문서에 접근할 수 있어야 한다. Git에 반영하지 않은 로컬 문서는 다른 PC에 자동 공유되지 않는다.

## IDEA-001 · 아이디어 메모와 마인드맵

### 사용자가 원하는 것

아이디어를 형식에 얽매이지 않고 자유롭게 입력해 저장하고, 쌓인 내용을 마인드맵처럼 보여주는 화면. 개발 중 떠오른 생각을 모아두는 별도 아이디어 저장소가 필요하다.

### 첫 구현 방향 제안 — 아직 미확정

1. 자유 메모 입력과 저장, 저장한 아이디어 목록·상세 조회부터 만든다.
2. 같은 데이터를 목록과 마인드맵 두 보기로 제공한다. 메모 원문은 그대로 보존하고 지도는 그 내용을 살펴보는 표현으로 사용한다.
3. 최초에는 사용자가 직접 연결한 부모·자식 관계나 주제로 묶는 단순한 지도부터 검토한다.

### 설계할 때 정할 것

- 개인 관리자 전용인지, 회원별 개인 공간인지, 공개할 아이디어도 있는지.
- 한 메모를 하나의 노드로 표현할지, 긴 메모를 여러 노드로 나눌지.
- 관계를 직접 편집할지, 자동 분류·AI 정리를 사용할지. **AI 사용은 아직 요청·확정하지 않았다.**
- 검색·태그·아이디어 상태가 필요한지, 지도에서 메모를 수정할 수 있어야 하는지.
- 실제 DB 저장과 접근 권한을 어떻게 적용할지. 아이디어 원문에 개인정보나 비공개 내용이 포함될 수 있으므로 기본 공개 여부를 명시적으로 정한다.

개발 전용 `/guide/ideas`에 화면 초안을 만들었다. 자유 메모 추가, 예시 분류 선택, 마인드맵/목록 전환, 선택한 원문 확인을 브라우저 메모리에서만 제공한다. 새로고침하면 입력이 사라지고 문서나 DB에도 저장하지 않는다. 화면 검토 후 DB·공개 범위·관계 편집을 설계하며 마인드맵 전용 라이브러리는 추가하지 않았다.

## IDEA-002 · 코드 놀이터

JS·TS·React·Vue·Java 등을 선택해 코드 입력 후 실행 결과를 확인하고 싶다는 제안. 예제는 console.log로 문자열 출력하기다. 현재는 설계 초안만 있으며 실제 실행기는 없다. 브라우저 실행부터 프레임워크 미리보기, 별도 Java 실행 환경까지 단계적으로 검토한다. 구체적인 범위는 [놀이터 설계](12-playground-plan.md)를 따른다.

## IDEA-003 · DB 놀이터

DB 연결과 쿼리를 테스트하는 실험 공간 제안. 코드 놀이터와 함께 설계만 정리했다. 운영 DB는 대상에서 제외하고 정해진 조회부터 시작하며, 자유 SQL·쓰기 실험은 별도 실험 DB와 권한을 준비한 뒤 검토한다.

## IDEA-004 · 예약 작업 현황

프로젝트 배치나 개인 Codex 예약 작업을 OZ에서 보고 싶다는 제안. 작업명·주기·최근 결과·다음 실행·실행 이력·결과 링크를 보여주는 방향을 논의했다. NAS 자체 작업과 Codex 작업의 실행 주체를 구분해야 한다. 현재 문서의 automation_jobs/job_runs는 설계이며 구현된 테이블이 아니다. Codex 외부 연동 가능 여부와 실제 예약 목록은 미확인이고 자동 동기화는 확정하지 않았다.

## IDEA-005 · 개발 DB SSH 터널 간편 실행

PowerShell 명령을 매번 입력하는 대신 로컬 바로가기나 버튼으로 개발 DB SSH 터널을 열고 연결 상태를 확인하고 싶다는 제안. 우선 로컬 실행 방식으로 검토하며 NAS에서 실행되는 웹 서버와 개발 PC의 터널을 구분한다. 인증 정보는 코드·문서에 저장하지 않는다. 현재는 아이디어 기록만 했으며 실행 기능은 구현하지 않았다.

## 기록 범위

이 목록은 현재 대화에서 확인한 아이디어다. 다른 대화·개인 메모·Codex 예약 목록 전체를 자동 수집한 결과는 아니다. 이미 만든 Markdown 뷰어·환경 구조도·OzAlert는 진행된 기능이므로 미구현 아이디어로 중복 등록하지 않는다. OzConfirm·OzDataGrid·OzDataEditGrid는 현재 이름 규칙의 예시였으며 구현하기로 확정한 항목으로 취급하지 않는다.

## 아이디어 저장소 상세 흐름과 사용자별 저장 방향

- 기본 화면은 우선순위 순 메인 아이디어 목록이다. 숫자 1이 최우선이며, 드래그 또는 순위 입력 후 Enter/포커스 이동으로 변경한다. 목록과 마인드맵은 같은 순서를 사용한다.
- 메인을 열면 원문과 가지를 보여준다. 댓글·설계·구현 이슈·연결 포스트 유형으로 본문을 추가하고 가지에 답글을 달 수 있다. 메인과 가지 본문은 수정 가능하다. 연결 포스트는 이번 초안에서 새 본문 유형이며 기존 게시글 검색/링크 연결은 구현하지 않는다.
- 마인드맵 첫 화면은 메인만 표시하고 메인 선택 후 해당 아이디어의 직속 가지를 표시한다. 답글 전체는 상세 목록에서 계층으로 확인한다.
- 이번 구현은 계속 브라우저 메모리 전용이다. 로그인·DB·다중 사용자 동시 수정은 아직 연결하지 않는다.

### 로그인 연결 시 DB 초안 (확정 스키마 아님)

| 대상         | 주요 필드                                                                          | 역할                         |
| ------------ | ---------------------------------------------------------------------------------- | ---------------------------- |
| ideas        | id, owner_id, title, content, category, status, sort_order, created_at, updated_at | 사용자별 메인 아이디어       |
| idea_entries | id, idea_id, parent_id, author_id, kind, title, content, created_at, updated_at    | 댓글·설계·이슈·포스트와 답글 |

기본 공개 범위는 비공개로 한다. owner_id/author_id는 클라이언트 값 대신 서버 세션에서 결정한다. 조회·수정·정렬·가지 추가 모두 아이디어 소유권을 서버에서 검사한다. parent_id는 같은 idea_id 소속만 허용하고 순환 연결을 막는다. 정렬 변경은 사용자 소유 목록 안에서 트랜잭션으로 갱신한다. 협업·공유는 후속 요구가 있을 때 별도 접근 권한으로 설계한다.

## IDEA-006 · 관리자 서버 검색·페이지네이션 전환

2026-10-22: 현재 전체 개발 목록을 받아 프론트에서 검색·페이징하는 방식을 유지하기로 했다. 데이터 증가·운영 관리자 연결 시 서버에서 검색조건을 적용하고 LIMIT/OFFSET 및 COUNT로 필요한 행과 전체 건수만 조회한다. 허용 검색조건·페이지 크기 검증, 정렬의 고유키 보조 순서, 조회/집계 조건 일치, 삭제 표시 제외를 함께 구현한다. 아직 서버 페이징은 적용하지 않았다.
