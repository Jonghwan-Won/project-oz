## 1. 마우스에 반응하는 히어로 배경이 무겁고 어색했다

**상황**
tiptap.dev처럼 세로 홈이 파인 유리(fluted glass) 뒤로 색이 흐르는 배경을 만들고 싶었다.
처음엔 화면 녹화본을 보고 비슷하게 흉내 냈는데,

- 가만히 있을 때도 번지는 효과가 계속 돌아 산만했고
- 효과 범위가 넓어 화면 전체가 출렁였으며
- 프레임이 떨어져 무거워 보였다.

**원인 분석**
겉모습만 따라 해서는 한계가 있었다. tiptap이 쓰는 MIT 라이선스 `shaders` 패키지의 소스를 직접 열어 보니
효과가 세 겹으로 나뉘어 있었다.

1. Swirl: 배경에서 천천히 일렁이는 두 색
2. ChromaFlow: 마우스가 움직일 때만 생기는 색 물결(속도장 + 액체량을 담은 격자)
3. FlutedGlass: 그 위를 굴절시키는 유리 홈

그리고 결과를 55% 불투명도로 흰 배경 위에 겹치고, 캔버스는 CSS 크기의 60%로만 그리고 있었다.

**해결**
- ChromaFlow를 CPU 128×128 격자로 직접 이식했다(`src/app/heroFlowField.ts`, MIT 출처 표기).
  - 마우스 속도로 브러시 크기를 정한다. 천천히 움직이면 거의 흔적이 남지 않는다.
  - 액체는 자기 흐름을 따라 흘러가고(semi-Lagrangian advection) 1초 정도에 걸쳐 사라진다.
  - 계산 결과를 텍스처로 올려 WebGL 셰이더에서 Swirl·유리와 합성한다.
- 성능을 다음과 같이 조절했다.
  - 캔버스를 60% 해상도로 그린다.
  - 액체가 움직이는 동안만 매 프레임 그리고, 가만히 있을 때는 약 30fps로 일렁임만 그린다.
  - 액체가 다 사라지면 텍스처 업로드를 멈춘다(최댓값이 1e-4 아래면 건너뜀).
  - 움직임 줄이기 설정, 탭 숨김, 화면 밖일 때는 정지 화면 한 장만 그린다.
- 시뮬레이션 1스텝은 약 0.3~0.65ms였다.

**곁가지 문제: 테스트가 30배 느렸다**
컴포넌트 테스트에서 시뮬레이션까지 `vm` 컨텍스트 안에서 돌렸더니 10~18초가 걸렸다.
Node 24가 TypeScript 타입을 바로 지워 주는 점을 이용해 시뮬레이션 모듈은 네이티브로 import하고
컴포넌트에만 주입했더니 약 0.2초로 줄었다.

**결과**
사용자 확인: "이거야 내가 원한게 이거야!!"

**배운 점**
겉모습을 흉내 내기 전에 원본이 어떤 층으로 이루어져 있는지 먼저 뜯어보는 편이 빠르다.

## 2. 여백을 통일했더니 다른 화면들이 왼쪽으로 쏠렸다

**상황**
/projects, /board의 좌우 여백을 메인과 맞추려고 공통 `.page` 클래스를
`max-width + margin: auto` 방식에서 좌우 패딩만으로 가운데를 맞추는 방식으로 바꿨다.
그 뒤 UI 가이드·실험실 화면이 왼쪽으로 붙었다.

**원인**
그 화면들은 `.page`에 자기 `max-width`(1100px, 1040px 등)만 덧붙여 폭을 좁히고 있었다.
가운데 정렬은 `.page`의 `margin: auto`에 기대고 있었는데, 그 부분을 지우면서 정렬이 사라졌다.
도움말·관리자 화면도 같은 구조였다.

**해결**
- 공통 `.page`는 원래 방식으로 되돌렸다. 1280px 화면에서는 패딩 방식과 위치가 같고, 차이는 스크롤바 폭(약 8px) 정도다.
- 진짜로 달랐던 /board만 메인과 같은 여백 변수 `--site-gutter`를 쓰게 했다.

**배운 점**
공통 클래스를 바꿀 때는 그 클래스에 덧붙여 쓰는 곳(`className="page ${s.xxx}"`)을 먼저 검색해야 한다.
이번에는 검색 한 번으로 영향 범위 8곳을 바로 찾을 수 있었다.

## 3. 관리자 에디터의 선택 상자만 글자가 컸다 (CSS 명시도)

**상황**
같은 리치 텍스트 에디터인데, 관리자 화면에서는 "본문/기본/크기" 선택 상자의 글자와 여백이 컸고
UI 가이드에서는 정상이었다. 운영에 올렸을 때 특히 눈에 띄었다.

**원인**
관리자 화면에는 입력칸 전체에 적용되는 공통 규칙이 있었다.

```css
.panel input:not([data-editor-color-input]) { font: inherit; padding: 12px; }
```

명시도를 따져 보면 이렇다.

| 규칙 | 명시도 |
|---|---|
| `.panel input:not([data-editor-color-input])` | (0, 2, 1) |
| `.toolbar .blockStyle` (에디터 쪽) | (0, 2, 0) |

`:not()` 안의 속성 선택자도 명시도에 더해지기 때문에 관리자 규칙이 에디터 규칙을 이겼다.
개발과 운영에서 다르게 보인 건 빌드 후 CSS 파일이 합쳐지는 순서 차이 때문으로 보인다.

**해결**
에디터 색상 입력에 이미 쓰던 예외 방식을 그대로 따랐다. 에디터 선택 상자에
`data-editor-control` 속성을 붙이고, 관리자 공통 입력 규칙 두 곳에서 `:not([data-editor-control])`로 뺐다.
`!important`나 선택자를 억지로 길게 쓰는 대신 기존 관례를 재사용했다.

**함께 고친 것**
- 코드 블록 버튼 `</>`: 기호 칸 너비가 24px로 고정돼 있어서 글꼴에 따라 두 줄로 꺾였다. 최소 너비와 줄바꿈 금지로 바꿨다.
- 이미지 삽입 버튼: 관리자(서버 업로드)는 아이콘, 가이드(브라우저 미리보기)는 글자라 달랐다. 아이콘 컴포넌트 하나를 두 곳에서 쓰게 했다.

**결과**: 화면 확인은 미확인.

## 4. "미사용 첨부파일 54개", 저장 경로 때문이 아니었다

**상황**
관리자 대시보드에 미사용 첨부파일이 54개로 나왔다. 처음에는 파일 저장 경로를
`uploads`에서 `uploads-dev`로 바꾼 탓이라고 짐작했다.

**검증** (개발 DB 읽기 전용 쿼리)

| 확인 항목 | 결과 |
|---|---|
| 전체 첨부파일 86개의 실제 파일 존재 여부 | 86개 모두 `uploads-dev`에 있음 |
| "사용 중" 판정 기준 | 경로가 아니라 `ProjectAsset`·`PostAsset` 연결 테이블(Asset ID) |
| 미사용 파일 ID나 파일명이 본문·프로젝트에 남아 있는지 | 0건 |
| 미사용 54개 중 환경 변수로 지정한 이력서·포트폴리오 PDF | 2개 |
| 같은 이름·크기의 사본이 "사용 중"으로 있는 파일 | 7개 (다시 올려 교체된 것으로 추정) |

경로 변경은 원인이 아니었다. 52개는 실제로 어디에도 쓰이지 않는 파일이었고,
2개는 집계 로직이 놓치고 있던 파일이었다.

**해결**
- 환경 변수로 지정한 PDF를 "사용 중"으로 세고, 삭제도 막았다. 판정은 `src/server/portfolio-assets.ts` 한 곳에 모았다.
  대시보드, 첨부파일 목록, 삭제 직전 재확인이 모두 같은 SQL 조건을 쓴다.
- 관리자 첨부파일 목록 출처 칸에 "이력서 PDF / 포트폴리오 PDF"로 표시한다.
- 남은 52개는 사람이 보고 지울 수 있도록 그대로 두었다.

**배운 점**
그럴듯한 가설(경로 변경)이 있어도 데이터를 먼저 확인해야 한다. 쿼리 몇 개로 원인을 좁히고,
실제로 고쳐야 할 부분(환경 변수 PDF 집계)을 따로 찾아냈다.

## 5. 다른 PC에서는 PDF 버튼이 "없음"으로 나왔다

**원인**
이력서·포트폴리오 PDF는 보안상 브라우저가 파일 ID를 고르지 못하게,
서버 환경 변수(`PORTFOLIO_RESUME_ASSET_ID`, `PORTFOLIO_DOCUMENT_ASSET_ID`)로만 지정한다.
`.env.local`은 Git에서 빠지는 파일이라 다른 PC에는 이 값이 없었다.

**해결**
DB에서 두 PDF의 ID를 찾아 해당 PC의 `.env.local`에 넣었다. 운영 서버에도 같은 값을 넣어야 한다는 점을 문서에 남겼다.

## 6. 로그인 후 원래 페이지로 돌아가게 하기 (오픈 리다이렉트 방지)

**요구**
관리자 화면에서 로그인 버튼을 누르면, 로그인한 뒤 원래 보던 페이지로 돌아와야 한다.

**위험**
`/login?next=https://악성사이트` 같은 링크로 로그인한 사용자를 외부로 보내는 오픈 리다이렉트가 생길 수 있다.

**해결** (`src/lib/return-path.ts`)
- 돌아갈 곳은 `?next=` 값, 없으면 같은 호스트의 Referer, 그것도 없으면 홈 순서로 정한다.
- 이 사이트 내부 경로만 허용하고 다음은 모두 `/`로 바꾼다: `//host`, 역슬래시 우회, 공백, 512자 초과, `/login`, `/api`.
- 위 경우들을 단위 테스트로 고정했다.

**결과**: 실제 GitHub 로그인으로 돌아오는 흐름은 미확인.

## 7. PDF를 미리보기 창에 띄우려다 되돌린 이유

**시도**
참고 사이트처럼 PDF를 바로 내려받지 않고 사이트 안 미리보기 창(iframe)에 띄우려고 했다.

**막힌 점**
- 사이트 전체에 `X-Frame-Options: DENY`가 걸려 있어 자기 사이트 iframe에도 뜨지 않는다.
- 첨부파일 응답의 `Content-Security-Policy: default-src 'none'; sandbox` 때문에 크롬 PDF 뷰어가 열리지 않는다.
- 휴대폰 브라우저는 iframe 안 PDF를 제대로 보여 주지 못하는 경우가 많다.

**결론**
보안 예외를 늘리는 것보다 새 탭에서 브라우저 PDF 뷰어로 여는 쪽이 단순하다고 판단해 되돌렸다.
남긴 변경은 다음과 같다.

- 포트폴리오 PDF 두 개만 CSP를 `frame-ancestors 'none'`으로 둔다. 뷰어는 열리고, 다른 사이트에 끼워 넣는 것은 막는다.
- 응답은 기본이 inline이고, `?download=1`일 때만 attachment로 보낸다.
- X-Frame-Options 예외는 원래대로 되돌렸다.

## 8. 작은 레이아웃 문제들

| 문제 | 원인 | 해결 |
|---|---|---|
| 모바일 첫 화면이 화면 중간에서 끝남 | 767px 이하에서 `min-height: auto`로 줄여 둠 | `100svh`로 되돌리고, 하단 독 자리를 safe-area까지 포함해 비움 |
| 모바일 하단 독과 '맨 위로' 버튼 높이가 어긋남 | 둘 다 56px인데 바닥 여백이 16px과 `max(20px, safe-area)`로 다름 | 1023px 이하에서 버튼을 `16px + safe-area`로 맞춤 |
| 기술 스택 로고(JPA·JSP·MSSQL·SVN)가 안 보임 | 글자 위주 로고를 32px로 줄임 | 원본 로고에서 글자를 빼고 기호만 잘라 사용(원본은 보관) |
| 화면마다 글꼴 지정이 제각각 | 오류 화면·에디터 팔레트가 Arial을 따로 지정함 | `--font-sans / --font-symbol / --font-serif` 세 변수로 통일하고, 파일이 없던 'Instrument Serif' 지정은 제거 |

## 정리하며

- 원인을 짐작으로 정하지 않고 확인했다. 쿼리(4번), 명시도 계산(3번), 영향 범위 검색(2번)으로 가설을 검증했다.
- 기존 관례를 재사용했다. 예외 속성 패턴(3번), 공통 판정 모듈(4번)이 그 예다.
- 안 되는 방향은 빨리 되돌렸다(7번). 단, 되돌리면서도 보안 설정은 최소 범위로만 남겼다.
- 경계값은 테스트로 고정했다. 리다이렉트 경로(6번), 환경 변수 PDF 집계(4번)가 그렇다.
