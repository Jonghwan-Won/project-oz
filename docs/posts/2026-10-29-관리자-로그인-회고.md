# 관리자 화면도 보여주고 싶은데, 저장은 나만 해야지

포트폴리오 링크를 넣으라는 곳에 이 사이트 주소를 써도 되나? 오늘은 이 생각에서 시작했다.

프로젝트도 있고 게시판도 있고, 이것저것 직접 만들고 있는 사이트이긴 한데. 막상 누군가한테 보여준다고 생각하니 연락할 곳부터 관리 화면까지 다시 눈에 들어왔다. 어제는 인용 하나 넣으려다 표 에디터까지 갔는데, 오늘은 연락처를 넣다가 로그인까지 왔다ㅋㅋ

## 연락은 어디로 하면 되는디

프로젝트를 읽은 사람이 연락하고 싶어도 이메일이 안 보이면 좀 애매하지 않나 싶었다. 짧은 안내랑 이메일, GitHub를 넣을 자리를 만들었다.

처음에는 이메일 옆에도 화살표가 붙어 있었는데, 이메일은 복사하는 쪽이 편할 것 같았다. 그렇다고 복사라고 글자로 쓰는 건 또 마음에 안 들었고. 복사 아이콘을 누르면 잠깐 체크 표시로 바뀌도록 했다. GitHub는 새 탭으로 열리게 바꿨다.

근데 복사 아이콘 바로 밑에 바깥으로 향하는 화살표가 있으니 묘하게 안 어울렸다. 줄도 맞추고 배경도 손봤다. 버그 제보랑 문의하기 카드에 넣었던 은은한 그라데이션도 같이 적용했다. 작은 영역인데 이것도 한 번에 끝나지는 않네.

문의는 로그인 없이 보낼 수 있으니, 답변이 필요한 사람은 연락처를 내용에 적어달라는 안내도 넣었다. 내용 입력하라는 말까지 반복할 필요는 없어서 그 문구는 뺐고, 카드 안의 버튼을 오른쪽으로 옮겨봤다가 아예 카드 자체를 누르는 방식으로 정리했다.

## 올려놓고 안 쓰는 파일들은 어쩌지

관리자 메뉴도 다시 정리했다. 분류 관리, 미디어 관리, 사이트 관리처럼 이름만 있는 메뉴를 두기보다 지금 실제로 쓸 수 있는 화면부터 만들고 싶었다. 공통코드는 프로젝트 관리나 게시판 관리와 비슷한 검색·목록 구조로 맞췄다.

첨부파일 쪽은 조금 더 구체적인 이유가 있었다. 에디터에서 사진을 올렸다가 지우거나, 첨부파일로 넣었다가 빼면 파일은 저장소에 남을 수 있다. 글에서는 없어졌는데 저장소에서는 계속 자리를 차지하는 거다.

그래서 파일명, 용량, 등록일, 사용 여부와 출처를 확인할 수 있는 화면을 만들었다. 미사용 파일만 골라보고 선택해서 삭제할 수 있게 했다. 비공개 글이나 프로젝트에 연결된 파일도 당연히 사용 중이다. 화면에 안 보인다고 안 쓰는 파일은 아니니까.

기준은 NAS 폴더를 무작정 훑은 결과가 아니라 DB에 등록된 파일과 저장된 콘텐츠의 연결이다. 아직 저장하지 않은 편집 내용까지 알아서 보호해 주는 건 아니라서, 파일을 정리하기 전에는 작성 중인 내용을 먼저 저장해야 한다.

검색도 입력할 때마다 목록이 바뀌는 식보다는 조건을 정하고 조회 버튼을 누르는 방식으로 맞췄다. 리셋 버튼도 넣고, 관리자 날짜는 yyyy-MM-dd로 통일했다. 파일명이 길면 줄임표로 표시하고, 출처는 긴 제목 대신 프로젝트나 게시글 정도만 보여주도록 했다.

## 문의가 왔으면 어디선가 봐야 하잖아

버그 제보랑 문의를 받는 창은 있는데, 들어온 내용을 확인하는 관리 화면도 필요했다. 문의사항 관리를 추가하고 유형이나 상태, 내용으로 조회할 수 있게 했다. 들어온 문의를 확인하고 처리 상태를 바꾸는 용도다. 답변을 자동으로 보내는 기능까지 만든 건 아니다.

대시보드에도 대기 중인 문의와 미사용 첨부파일 개수, 용량을 넣었다. 프로젝트랑 게시글 카드에는 노출·미노출 개수도 보이게 했다. 처음에는 카드가 너무 휑해 보여서 뭘 더 넣을까 했는데, 관리 화면이면 지금 확인해야 할 게 뭔지 보여주는 게 맞겠다 싶었다.

이 정도 만들고 나니 관리자 화면도 굳이 나만 볼 필요가 있나 싶었다. 이 사이트를 어떻게 만들고 관리하는지도 포트폴리오의 일부로 보여줄 수 있지 않을까.

## 구경은 해도 되는데 저장은 안 됩니다

실험실이랑 공통 UI 가이드, 관리자 화면도 둘러볼 수 있게 열고 싶었다. 대신 등록이나 수정, 삭제는 나만 할 수 있게.

여기서 한 번 생각이 엇갈렸다. 내가 원한 건 기존 관리자 화면의 모양을 그대로 보여주고, 권한이 필요한 버튼만 못 누르게 하는 거였다. 그런데 처음에는 공개용 목록을 따로 단순하게 만들고 일부 메뉴를 숨기는 방향으로 갔다.

그건 내가 보여주고 싶었던 화면이 아닌디. 그래서 기존 목록, 검색 영역, 상세 팝업을 그대로 쓰는 쪽으로 다시 맞췄다. 프로젝트와 게시글은 상세 내용이나 미리보기를 볼 수 있지만, 입력란과 에디터 도구, 업로드, 저장과 삭제는 비활성화했다. 문의랑 공통코드 메뉴도 없애는 게 아니라 보이되 누르지 못하게 했다.

화면에서 못 누르게 하는 것만으로 끝낼 수는 없었다. 주소나 API를 직접 호출해도 변경되지 않도록 서버에서도 관리자 권한을 확인하게 했다. 공개 프로젝트와 게시글만 조회할 수 있는 범위도 따로 지켰다.

## 로그인 버튼을 누른다고 로그인이 되는 건 아니네

관리자는 GitHub 계정으로 로그인하는 방식으로 정했다. 이름이나 이메일이 비슷한 사람이 아니라 지정한 GitHub 고유 계정만 로그인할 수 있게 했다.

처음 로그인 화면에 들어갔을 때는 설정을 준비하고 있다는 안내만 나왔다. 화면이 있는 것과 실제 공급자 연결이 끝난 건 다른 일이었다. OAuth 앱과 콜백을 설정하고 연결한 뒤에는 직접 버튼을 눌러 로그인까지 확인했다.

그다음엔 로그인했는데 헤더에 여전히 로그인이라고 떠 있었다. 로그인 성공 후 어디로 갈지도 빠져 있었고, 화면도 너무 휑했다. 세션에 맞춰 로그인·로그아웃 표시가 바뀌게 하고, 성공하면 메인으로 돌아가도록 했다. 로그인 문구도 페이지 안에서 한글·영어를 조건문으로 나누던 걸 기존 다국어 TS 파일로 옮겼다.

로그인 화면을 다듬던 중의 모습이다. 아래 둘러보기 버튼도 GitHub 로그인 버튼과 같은 너비로 다시 맞췄고, 위쪽 문구를 뺀 만큼 여백도 줄였다.

## disabled라면서 이건 왜 눌리냐

비로그인 상태로 하나씩 눌러보니 빠진 데가 또 나왔다. 프로젝트 상세에서 입력은 못 하는데 썸네일이나 첨부파일 이름을 누르면 다운로드가 됐다. 파일 선택 버튼만 막는다고 끝나는 게 아니었다. 상세와 미리보기의 첨부 링크도 같이 확인했다.

대시보드에는 미사용 파일이 몇 개라고 나오는데 첨부파일 목록에서는 안 보이는 것도 이상했다. 미사용 파일 확인 버튼까지 막아놨으니, 메뉴로는 들어갈 수 있는 화면인데 대시보드에서는 못 가는 상태였다.

집계와 목록을 맞추고, 당시에는 비로그인도 미사용 파일의 메타데이터를 볼 수 있게 했다. 현재는 원본 파일명을 숨기고 파일명 검색도 관리자에게만 제공한다. 대신 연결된 비공개 콘텐츠의 제목이나 실제 파일 다운로드는 보호했다. 단순히 전부 보여주거나 전부 막는 것보다는 어디까지 보여줄지 구체적으로 정하는 일이 필요했다.

대시보드 숫자도 대시로 가리기보다 기존처럼 집계는 보여주고, 제한이 필요한 동작을 비활성화하는 쪽으로 정리했다.

## 결국 아이콘 옆 글자까지

로그인할 때 버튼 문구가 연결 중으로 바뀌는 대신, 중복 클릭을 막고 기존 공통 로딩 오버레이를 보여주도록 했다. 로그아웃도 같은 방식으로 맞췄다.

그런데 이번에는 반투명이어야 할 로딩 화면이 뒤를 너무 가렸다. 배경 오버레이와 전체 화면 모달에 색과 블러가 겹치는 구조를 정리해서, 모달은 투명하게 두고 배경에만 반투명 효과가 들어가도록 바꿨다.

헤더의 로그인과 로그아웃 글자 크기도 달랐다. GitHub 아이콘이랑 글자를 가운데로 맞췄는데, 이번에는 글자만 조금 위로 떠 보였다. 마지막에는 문구를 2px 아래로 내리는 것까지 했다. 분명 관리자 기능 만들고 있었는데 왜 여기서 글자 위치를 보고 있지ㅋㅋ

공통 그리드도 결과가 없을 때 가운데에 검색 결과가 없습니다.라고 나오도록 통일했다. 파일이 없습니다, 등록된 그룹이 없습니다처럼 화면마다 달랐던 문구도 같이 정리했다.

## 오늘은 여기까지

자동 테스트에서는 권한 없는 요청의 차단, 읽기 전용 입력과 버튼, 파일 조회 범위, 로딩 중 중복 클릭 같은 부분을 확인했다. 타입 검사와 운영 빌드도 통과했다. 그치만 직접 눌러보니 빠진 링크나 어색한 정렬이 계속 나왔다. 어제도 비슷한 얘기를 썼는데 오늘도 똑같네.

이번 작업은 로컬 개발 환경에 반영한 상태다. 운영용 OAuth 설정과 DB·저장소 구성, 실제 배포까지 끝났다는 뜻은 아니다. 마지막 오버레이나 글자 위치도 화면에서 더 써보면서 확인해야 한다.

포트폴리오에 이 주소를 넣어도 될까 하다가, 다른 사람이 어디까지 볼 수 있고 나는 어디서 관리할 건지까지 정한 하루였다. 이제는 보여줄 화면뿐 아니라 그 뒤에서 정리할 곳도 조금씩 생기고 있다.
