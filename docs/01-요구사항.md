# 요구사항과 화면

이 문서는 제품 목표와 요구사항을 기록합니다. 실제 구현 여부는 [현재 구현 상태](10-현재-구현-상태.md), 현재 운영 정책은 [접근 정책](16-접근-정책.md)을 기준으로 확인하세요. 이 문서에 있는 모든 항목이 출시 범위로 확정된 것은 아닙니다.

## 메뉴
| 1차 | 2차/분류 | 주요 화면 |
|---|---|---|
| 홈 | 없음 | 최신 게시글, 대표 프로젝트, 실험실 작업 |
| 소개 | 프로필·경력 | 업무 경험, 기술, 연락 안내 |
| 프로젝트 | 전체·웹사이트·인디게임·편의성 앱 | 소개, 이미지, 개발 기록, 사이트/스토어 링크 |
| 실험실 | 전체·아이디어·개발 중·테스트 중 | 진행 상태와 개발 기록 |
| 게시판 | 전체·AI 정보·연예 이슈·채용/공채·주식/코인·부동산 | 목록, 카테고리별 모아보기, 상세 |
| 도움·문의 | FAQ·버그 제보·문의하기·연락 안내 | 공개 도움말, 비공개 문의와 내 문의 |
| 관리자 | 글·자동화·프로젝트·문의·메뉴/권한 | 권한 있는 사용자만 접근 |
| 계정 | 로그인·내 문의·로그아웃 | 계정 상태·소유 데이터 |

메뉴 트리와 콘텐츠 카테고리는 별도 개념이다. 메뉴가 카테고리 페이지를 가리킬 수 있으나, 메뉴 삭제로 글을 삭제하지 않는다. 메뉴에 임의 실행 코드/SQL/권한 로직을 저장하지 않는다.

## 게시판
- 기본안: 운영자 발행형 정보 게시판. 회원의 일반 글 작성·댓글은 현재 필수 범위가 아니다.
- 전체에서는 공개 시각이 된 모든 카테고리 글을 최신순으로 표시한다. 카테고리 선택 시 하위 카테고리 포함을 기본으로 한다.
- 페이지당 20개 기본, 최대 50개. 제목 검색은 우선 DB 검색으로 시작한다.
- 작성 유형(MANUAL/AI), 검토 상태, 공개 상태, 작성일·수정일, 출처 링크를 관리한다.
- Markdown 본문을 기본으로 하되 raw HTML은 비활성화한다. 실제 편집기는 구현 시 확정한다.
- 게시글 예약 발행과 AI 예약 생성은 서로 다른 동작이다.

## 프로젝트와 실험실
- 한 프로젝트의 lifecycle: IDEA → BUILDING → TESTING → RELEASED → ARCHIVED.
- lifecycle과 프로젝트 노출 여부(`isVisible` boolean)는 별도 필드다. 개발 중이라도 사이트에 표시할 수 있다.
- 공개 프로젝트는 RELEASED + PUBLIC, 실험실은 IDEA/BUILDING/TESTING + PUBLIC.
- RELEASED로 바꿔도 ID·slug·기록·링크를 유지한다. 상세 URL은 DB ID 기반 /work/[id]로 사용한다.
- 프로젝트 유형은 카테고리로 분류한다. 웹사이트, 앱스토어 등 외부 링크는 여러 개 등록 가능하다.
- 보관된 프로젝트는 검색·직접 URL의 공개 정책을 명시하고 보관 표시한다. 비공개 프로젝트는 권한 없으면 404.

## 문의
- FAQ와 연락 안내는 비로그인 공개. 문의/버그 제보는 로그인 후 등록하는 것을 기본안으로 한다.
- 작성자 본인과 inquiry.manage 권한 사용자만 내용·첨부·답변을 조회한다.
- 최초 버전은 텍스트 문의와 화면 URL. 첨부 업로드·이메일 알림은 단계적으로 추가한다.
- 문의 목록, 상태(OPEN/IN_PROGRESS/ANSWERED/CLOSED), 관리자 답변 제공.

## 화면 공통
- 빈 목록, 로딩, 저장 실패, 로그인 만료, 권한 거부, 모바일 메뉴, 긴 제목을 처리한다.
- 공개 화면과 관리자 화면은 레이아웃을 분리한다.
- 관리자 글 작성은 create, 수정은 update, 발행은 publish 권한으로 구분한다.
- 데모용 역할 선택 UI는 운영 코드에 포함하지 않는다.
